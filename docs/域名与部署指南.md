# 域名与部署指南（Netlify 版）

> 适用对象：「北京科技大学 寒假招生宣传小队 / 打道回阜队」里负责运维的同学（不写代码，也没有网站维护经验）。
> 站点形态：小队的官方小队站，纯静态中文站点（小队介绍 / 学生答疑 / 资料分享 等），无后端、无数据库。
> 现状：**已经上线**在 <https://dadaohuifu.netlify.app>，7 个页面 + 404 页全部 200，`rss.xml` / `sitemap.xml` 也在。
> 构建方式：仓库根目录执行 `npm run build`（内部是 `node build.mjs`），**没有第三方依赖、不需要 `npm install`**，产物目录是 `dist`。
> 托管平台：**Netlify**（Free / Starter 计划，邮箱注册，不需要手机号）。

## 为什么最后落在 Netlify

前面试过两个平台，都被具体障碍挡住：Cloudflare 对队里那台电脑的出口 IP 直接返回 9109（位置被拒绝）；Vercel 注册时要美国手机号验证，走不通。Netlify 只要邮箱就能注册，而且实测可达 —— 于是定在这里。
下文只写 Netlify 的操作。

## 一、选域名：判定清单

一条一条过，全部打勾再买。域名买错要换，等于后面的配置全部重做。

| 判定项 | 怎么判定 | 合格标准 |
| --- | --- | --- |
| 后缀 | 先想清楚要 `.com`、`.cn`、`.net` 还是 `.me` | 小队站首选 `.com`；被占了再考虑 `.cn` / `.net` |
| 是否必须 `.com` | 这个网址会不会印在宣传单、贴进答疑群、做成二维码 | 要给同学看、要长期用，优先 `.com` |
| 长度 | 数一数主域名（不含后缀）有几个字符 | 建议 4–15 个字符；整体不超过 25 个字符（二维码更好扫、念出来更短） |
| 易读易念 | 在电话里念一遍，让同学复述一次 | 对方能一次听对，且不会拼错 |
| 拼写歧义 | 有没有连字符 `-`、数字 `0` 与字母 `o`、`1` 与 `l` | 尽量不用连字符和数字；必须用时只用一处 |
| 小队可识别 | 是否含 `ustb` 或队名拼音（现在用的是「打道回阜」= `dadaohuifu`） | 一眼能看出是北科大寒招小队 |
| 记忆成本 | 隔一天不看，还能默写出来吗 | 能默写 |
| 价格与续费 | 注册商页面上的「首年价」和「续费价」分别看 | 只看续费价能不能接受；**价格以官网/注册商页面为准** |
| 续费陷阱 | 是否自动续费、是否绑「多年优惠」、转入转出是否有费用 | 打开自动续费防丢域名；不接受必须一次买 5 年才便宜 |
| 商标与校名风险 | 这个词是不是知名品牌；缩写会不会被误认为学校官方主站 | 不带他人商标；也别做得像「北科大官网」，避免误导 |

两条只对本站有意义的判断：

- 招生宣传场景下域名常被写进海报和二维码，**短**比「好看」更重要。
- 不要为「看起来专业」选生僻后缀，新手最容易踩的坑是续费价格暴涨。

## 二、在哪买：渠道取舍与注册前准备

### 2.1 四个渠道对比

| 渠道 | 适合谁 | 优点 | 要注意 |
| --- | --- | --- | --- |
| Netlify 内建购买（Domain management → Add a domain → **Buy a new domain**） | 已经决定用 Netlify、想少一个账号的人 | 买完自动接进当前项目，DNS 由 Netlify DNS 管，证书也能自动出通配符；具体后缀与是否可买**以页面为准** | 界面全英文；可选后缀比大注册商少 |
| 阿里云 | 想要中文界面、支付宝付款的人 | 全中文、支付宝/微信付款、客服说中文、`.cn` / `.com` 齐全 | 需要做域名**实名认证**（境内注册商通行要求，认证通过才算注册成功）；DNS 在阿里云云解析，接 Netlify 时按 5.2 手动加记录 |
| 腾讯云 | 同上，习惯腾讯系产品的人 | 全中文、微信支付、与 DNSPod 打通 | 同样需要实名认证；接 Netlify 的方式同阿里云 |
| Namecheap | 想要英文界面但不想被 Netlify 可选后缀限制的人 | 后缀选择多、whois 隐私免费、常有大额首年优惠 | 促销首年便宜、**续费会明显变贵**；英文界面；国际支付 |

建议（按省事程度排序）：

1. **Netlify 内建购买**：省一个账号，DNS 就在同一个面板，5.2 的记录不用去别处抄。
2. **阿里云 / 腾讯云**：全中文、付款方便、有客服；代价是 DNS 记录要手动加两条（A + CNAME，见 5.2）。
3. **Namecheap**：只在你想要的后缀 Netlify 不卖时才选。

注意：域名是**小队共用资产**。用小队公共邮箱（或能长期交接的邮箱）注册，账号密码交给下一届负责人。用个人 QQ 邮箱注册、人毕业了就找不回，是小队站最常见的「死域名」原因。

### 2.2 注册前要准备什么

| 准备项 | 说明 | 大概要多久 |
| --- | --- | --- |
| 一个能长期收信的邮箱 | 注册商与 ICANN 都会发验证信；邮箱没验证，域名可能被挂起 | 当场，几分钟 |
| 实名认证材料（境内注册商） | 阿里云 / 腾讯云注册 `.com` `.cn` 等需要提交实名信息并等审核，材料清单**以注册商页面为准** | 通常当天，个别 1–2 个工作日 |
| 支付方式 | Netlify / Namecheap：支持国际支付的卡或对应渠道；阿里云 / 腾讯云：支付宝、微信、银行卡 | 当场 |
| 备选域名 2–3 个 | 第一个被占时不用临时乱选 | — |
| 一个 Netlify 账号 | **邮箱注册即可，不需要手机号**；用 GitHub 登录也行 | 几分钟 |

价格一律不写数字：**以官网为准**。看价格请看「续费价」。

## 三、备案说明：什么时候需要，什么时候不需要

这一节只讲边界，不做法律结论。判断标准一句话：**看网站最终由哪台机器、在哪个地区对外提供服务。**

### 3.1 本项目的现状

小队站托管在 Netlify，内容从 Netlify 的全球节点分发，**不落在任何中国大陆境内的服务器上**。这种情况下通常不需要办理 ICP 备案，域名可以正常解析和访问。

### 3.2 什么情况会变成「需要备案」

出现下面任一情况，就该把备案当成前置条件，先备案再切流量：

- 把站点搬到**中国大陆境内**的云服务器（ECS / CVM / 轻量应用服务器）。
- 给站点接入**中国大陆境内**的 CDN 加速节点、或境内对象存储的静态托管。
- 用境内的「建站」类产品托管内容。
- 把站点交给**学校网络中心托管到校园网服务器**——同属境内托管，不但要备案，通常还要走学校审批。

原因很直接：备案是**按接入服务商**办理的，境内服务商开通网站服务前会要你提供已备案的域名；境外托管没有这个接入环节。

### 3.3 几个容易混淆的点

- **买域名不等于要备案**：境内注册商要你做的是**实名认证**，那是域名管理要求；备案是网站接入环节的要求。
- **域名注册商在境内、托管在境外**：仍属「境外托管」，通常不需要备案。
- **备案不是一劳永逸**：换接入商、换服务器地域，备案信息要变更。
- **不确定就问**：日后若要用境内服务，直接问云厂商备案控制台/客服或学校网络中心，他们的口径才是最终口径。官方入口：<https://beian.miit.gov.cn/>（打开慢或被拦属常见现象，换网络再试）。

### 3.4 一条实操建议

如果未来有搬到境内（或交给学校托管）的可能，**买域名时就注册在境内注册商并完成实名认证**，日后备案时域名这一环不会卡住。境外注册商的域名，部分省份备案流程更麻烦，**以接入商要求为准**。

### 3.5 如果要在国内访问更快

先说结论：**境外托管不保证中国大陆的可用性与速度**。任何托管在境外的站点都可能遇到延迟、限速甚至打不开，这不是配置能彻底解决的问题。所以这一节只讲取舍。

三条路，按「改动量从小到大」排：

| 路线 | 具体做什么 | 要不要备案 | 代价与限制 |
| --- | --- | --- | --- |
| **A. 保持 Netlify 不动** | ①用自己的域名，别只发 `*.netlify.app` 网址（自有域名更不容易被标记或拦截，但没有哪个域名能免疫）②把字体、统计脚本等第三方资源改成站点自带 | 不需要 | 改动最小、零成本；高峰期仍可能慢或打不开 |
| **B. 换成国内对象存储 + CDN** | 把 `dist` 上传到境内对象存储，前面挂境内 CDN，域名解析指过去 | **需要**（境内托管/接入） | 国内访问最快最稳；代价是要备案（需时间）、多维护一套账号，每次发布要传两处 |
| **C. 双托管（Netlify + 境内镜像）** | 同一份 `dist` 同时部署到 Netlify 和境内一个镜像，用不同域名或分流策略对外 | 境内那份**需要** | 两边都能用、可做对照；代价是两份都要维护、内容要同步 |

一句真话：大多数小队站先做 A 就够了；只有当「答疑群里的同学经常打不开」成为真问题，才值得为 B / C 付备案与维护成本。

## 四、两条部署路径

实际情况：本站是**用 API 上传 `dist` 上的线**（不是 Git 集成）。两条路都能用，A 更适合长期维护，B 更适合「不想碰 Git」。

### 4.1 路径 A：连接 Git 仓库，推送即自动部署

1. 登录 Netlify，在团队面板选 **Add new project** → **Import an existing project**。
2. 选 **GitHub**（或 GitLab / Bitbucket），按提示授权 Netlify 访问仓库。
3. 选中仓库后填发布设置：
   - **Build command**：填 `npm run build`。
   - **Publish directory**：填 `dist`。
   - **Base directory**：代码在仓库根目录就留空；在子目录才填。
   - 不用管依赖安装：本项目**没有依赖**，Netlify 跑 `npm install` 也会很快结束。
4. 点 **Publish**。
5. **看到什么算成功**：项目 Deploys 里出现一条 **Published** 的部署，`*.netlify.app` 能打开首页。
6. 上线后**立刻检查 4.3（访问保护）**——新项目默认可能是 private，访客会拿到 401。

> 官方术语：Netlify 的「Build command / Publish directory」就是别的平台说的「构建命令 / 输出目录」。**只有 publish directory 里的文件才会被部署**。

### 4.2 路径 B：手动上传 dist（三种做法，任选）

先本地构建：

```bash
cd <仓库根目录>
npm run build
```

产物在 `dist/`（含 `index.html`、`404.html`、`rss.xml`、`sitemap.xml`）。

**B-1 拖拽（Netlify Drop，最直观）**

1. 打开 <https://app.netlify.com/drop>（已登录时也可以拖到团队 Projects 页面底部的拖拽区）。
2. 把 `dist` **文件夹本身**拖进去（不要拖 zip，也不要只拖里面的散文件）。
3. **看到什么算成功**：几秒后出现站点地址，打开首页能看到内容。
4. 之后要更新：把新的 `dist` 拖到该站点 **Deploys** 页面底部的拖拽区，会生成一条新部署。

**B-2 Netlify CLI（有 Node.js 就行）**

```bash
npm install -g netlify-cli   # 只需一次
netlify login                # 浏览器授权
netlify deploy --prod        # 在仓库根目录执行，发布到正式地址
```

不带 `--prod` 时只生成预览部署（Draft），不会替换线上版本——**新手最容易在这里以为「部署成功了」，其实线上没变**。

**B-3 用仓库里的现成脚本（本站实际用的方式）**

仓库里的 `scripts/netlify-deploy.mjs` 会：确保站点存在 → 用 `scripts/zip.mjs` 把 `dist` 打包 → 走官方 REST API 上传 → 轮询到 `ready`。

```bash
# Token 在 Netlify 面板：User settings → Applications → Personal access tokens
NETLIFY_TOKEN=你的token node scripts/netlify-deploy.mjs dadaohuifu
```

**看到什么算成功**：终端打印「打包完成：N 个文件」「部署已提交」「站点地址」与本次部署预览地址；最后一行是 `https://dadaohuifu.netlify.app`。

> 这两个脚本在 `scripts/` 里，随仓库一起走，换电脑克隆下来就能用。

### 4.3 坑一：新建站点默认开启访问保护，所有人打开是 401

**现象**：访问 `https://dadaohuifu.netlify.app`（或你自己的域名），浏览器跳到一个要求登录的页面，地址变成 `app.netlify.com/edge-access`，响应码 401。你自己登录着浏览器时看不出问题，发给同学就全都打不开。

**原因**：Netlify 的**项目可见性（Project visibility）**。官方文档写明：如果团队开启了「默认 private」，新项目会以 private 起步，**只有登录的团队成员才能查看**，访客会被 Netlify 登录页拦住。

**解决（面板）**：

1. 项目页 → **Project configuration** → **General** → **Visitor access** 里的 **Project visibility**。
2. 把选项从 **Private** 改成 **Public**（密码保护是付费计划才有），保存。
3. 另一种入口：项目概览上的 **Make public** 按钮（需要项目已经有至少一次成功的生产部署）。
   > 若你的界面里这一块叫 **Access control** 或 **Access & security**，是同一处设置，找含 «visibility» 或「public/private」的开关即可。

**解决（API）**：站点对象上的 `sso_login: false` 就是关掉访问保护（字段名以官方 API 文档为准）。

**验证**：开一个**无痕窗口**（不登录任何账号）访问站点，应直接看到首页；再做一次手机流量访问。这一步不做，你永远不会知道访客看到的是登录页。

### 4.4 坑二：子页面全部 404（打包时用了反斜杠路径）

**现象**：首页正常，但点任何子页面都是 404；解压你上传的 zip 一看，条目名是 `qa\index.html` 这种**反斜杠**。Netlify 按字面理解文件名，于是这些文件等于不存在。

**原因**：Windows 的 `Compress-Archive`（PowerShell）和 .NET Framework 的 `ZipFile.CreateFromDirectory` 都会写反斜杠分隔的条目名。ZIP 规范要求正斜杠，Netlify 不兼容这种写法。

**解决**：换一个保证正斜杠的工具打包，或干脆不打包：

| 工具 | 怎么做 | 说明 |
| --- | --- | --- |
| `scripts/netlify-deploy.mjs`（仓库自带） | 见 4.2 的 B-3 | 内部的 `zip.mjs` 是零依赖手写打包器，条目名用正斜杠，本站就是用它上线的 |
| Netlify CLI | `netlify deploy --prod` | 不自己打包，直接传目录，最省心 |
| Netlify Drop | 直接拖 `dist` 文件夹 | 不经过 zip，天然避开这个坑 |
| 7-Zip / 命令行 `zip -r`（Git Bash、WSL） | 正常压缩 `dist` | 都写正斜杠，可用 |

**自检方法**：上传前解压看一眼，条目名必须是 `qa/index.html` 这样带正斜杠的；或直接上传后逐个页面点一遍，别只看首页。

### 4.5 坑三：免费计划的 Powered by Netlify 徽标关不掉

**事实**：Netlify 官方文档写明——**2026-08-19 及之后新建的 Free 计划项目，默认带 Powered by Netlify 徽标**；徽标出现在页面右下角，访客点开是一个「去 Netlify 建你自己的站」的卡片。Personal / Pro 计划可以关（项目设置 **Project configuration → General → Powered by Netlify badge**），**如果这个开关是锁着的，就说明当前计划不允许关**。

**本站实测**：直接调 API 尝试关闭，返回 `422`：`{"code":422,"message":"Removing the Netlify badge is not available on this plan"}`（实测返回，原文如上）。也就是说：**免费计划上这不是配置问题，是计划限制，关不掉。**

**取舍**：

| 选择 | 好处 | 代价 |
| --- | --- | --- |
| **接受徽标**（推荐） | 什么都不用做，零成本；徽标不显示你的任何信息（不提队伍、不显示流量数据），只是右下角一个小图标 | 页面上多一块第三方品牌元素，观感上没那么「干净」 |
| **换 GitHub Pages** | 免费、无徽标、同样支持自定义域名与自动 HTTPS | 要会一点 Git；没有拖拽上传；构建与部署要另配；迁移一次要重配域名解析 |

一句话：**要么接受徽标，要么换平台，没有第三个选项**。别在这一项上反复试 API，结果只会是同一个 422。

## 五、绑定自定义域名（含 DNS 记录表）

### 5.1 第一步：把域名加进项目

1. 项目 → 左侧边栏 **Domain management**。
2. 在 **Production domains** 里点 **Add a domain**。
3. 选 **Add a domain you already own**。
4. 输入域名（例如 `example.com`）→ **Verify** → 确认 **Add domain**。
5. 加进去的第一个域名默认就是**主域名（primary domain）**。
6. 加完会显示 **Pending DNS verification** —— 点它，Netlify 会把**你这个域名需要的确切记录**列出来（值是按域名定制的，照它抄最稳）。

### 5.2 做法一：DNS 留在原注册商，只加两条记录

Netlify 官方给的形态非常明确（原文照译）：

> 如果 DNS 服务商支持 ALIAS / CNAME-flattening，根域名把 «alias» 指向 `apex-loadbalancer.netlify.com`；**不支持就把根域名做成 A 记录指向 `75.2.60.5`**。www（或其他子域名）做一条 CNAME 指向 `site-name.netlify.app`。

落到本站（站点名 `dadaohuifu`）：

| 类型 | 名称（主机记录） | 值 | TTL | 说明 |
| --- | --- | --- | --- | --- |
| `A` | **@**（根域名 `example.com`） | `75.2.60.5` | 自动 / 600 | 官方标准网络的负载均衡地址；你的 DNS 不支持 ALIAS 时就用它 |
| `ALIAS` 或 CNAME-flattening | **@**（根域名） | `apex-loadbalancer.netlify.com` | 自动 | 只有服务商支持这类「根域名 CNAME」时才用，二者**选一个**，不要同时加 |
| `CNAME` | `www` | `dadaohuifu.netlify.app` | 自动 / 600 | 子域名指向站点默认地址 |

三点提醒：

- 值不要带 `https://`，也不要带结尾斜杠。
- **同一个主机名不要同时留 A 和 CNAME**，多出来的旧记录会让验证一直失败。
- 各家 DNS 的「名称」写法不同：阿里云/腾讯云在主机记录里填 @ 与 www；有的服务商要求填完整 `www.example.com`。**若你的界面与上文不同，就找含「记录类型 / 主机记录 / 记录值」的入口，按面板提示的名称格式填。**

### 5.3 做法二：把 nameserver 交给 Netlify DNS

适合「这个域名只给小队站用」的情况：

1. 添加域名时选使用 Netlify DNS（或在 **Domain management** 里为域名启用 Netlify DNS）。
2. 面板会给你**四条专属 nameserver**，格式类似 `dns1.p01.nsone.net`（**每条都不一样，以你的域名面板显示为准**）。
3. 到注册商把 nameserver 改成这四条，保存。
4. 之后 DNS 记录由 Netlify 托管，证书与通配符也能自动处理。传播最长 **48 小时**。

代价：你在原 DNS 上的一切记录都要搬过来（邮箱验证、其他子域名等）。好处：不用手抄 A / CNAME，避开 5.2 的抄错风险。

### 5.4 www 与根域名的一致性

- 建议**两个都加上**（`example.com` 与 `www.example.com`）：先在 Production domains 里定一个 primary，另一个作为别名（domain alias）。
- 想让访问 `www` 的同学统一落到裸域（或反过来），在 **Domain management** 里用域名跳转/别名设置指到 primary；具体选项位置**以面板为准**。
- **看到什么算成功**：两个地址都能打开，且最终停在同一个域名上，内容一致。

### 5.5 怎么确认配置真的生效

```bash
nslookup example.com 1.1.1.1
nslookup www.example.com 1.1.1.1
```

**看到什么算成功**：`nslookup` 返回的地址与 Netlify 面板要求的一致；`www` 那条的 `Canonical name` 指向 `dadaohuifu.netlify.app`；Domain management 里域名不再是 Pending DNS verification。

### 5.6 日后在同一域名下加页面 / 换内容，会影响域名吗？

**不会。** 域名绑定是**项目级**的。

- 你绑的是「`example.com` → `dadaohuifu` 这个项目」，不是某个页面。
- 新增页面、删页面、改文案、换配色换图片，**都不用重新配域名**。DNS 记录和 Domain management 里的条目保持不动。
- 你只需要**重新构建并部署**（A 路径推代码，B 路径重传 `dist`）。部署变 Published 后新页面立刻可访问。
- 新页面能不能打开，只取决于产物里有没有对应文件（例如 `dist/qa/index.html`），和域名无关。
- 唯一别动的是：**站点名**（`dadaohuifu`，改了 `*.netlify.app` 地址会变）和 Domain management 里的域名条目。

一句话记法：**域名绑的是站点，内容改的是文件；改文件不用碰域名。**

## 六、HTTPS / 证书 / 域名跳转

### 6.1 证书是自动的

官方原文：新站点在 `*.netlify.app` 上**立即就是 HTTPS**；添加自定义域名后，Netlify 会**自动用 Let's Encrypt 签发证书**，并在需要时自动续期。你不需要上传任何证书文件。

查看状态：**Domain management → HTTPS**。浏览器打开 `https://example.com` 有小锁，就是生效了。

### 6.2 证书一直 Pending 的常见原因

1. **DNS 还没指向 Netlify 就去点了签发**。顺序必须是：记录先对 → 再签发。等 `nslookup` 确认记录正确后，回 **Domain management → HTTPS** 重新验证/签发。
2. **有 CAA 记录限制了签发机构**。若你加过 CAA，需要允许 Let's Encrypt；官方还给了带账号锁定的写法（可选）：
   ```text
   example.com  300  IN  CAA  0 issue "letsencrypt.org;accounturi=https://acme-v02.api.letsencrypt.org/acme/acct/54403714"
   ```
3. **DNS 传播还没完成**：最多等 48 小时（官方说明）。
4. 同名主机上还有旧的 A / CNAME 冲突记录没删。

### 6.3 关于 http → https

Netlify 给站点提供 HTTPS 并自动签发证书。**至于 `http://` 打开时会不会自动跳 `https://`，请自己实测一次**：地址栏输入 `http://example.com` 回车，看是否变成 `https://`。
（这条属于平台行为细节，本文没有找到可引用的官方原句，所以不做承诺；若你的站点停在 http 不跳转，记录现象后去 Netlify 支持论坛确认，不要凭猜测改 DNS。）

> HSTS 这类「浏览器强制只用 https」的设置不需要开，配错很难回退，小队站用不到。

## 九、日常发布流程

> 本站当前走的是 **A 路径 + GitHub Actions**：仓库 `.github/workflows/deploy.yml` 已经在跑，推送代码即自动构建上线。下面的 9.1 是这条路；9.2 是手动兜底。

### 9.1 改了页面内容之后（推荐：push 即自动部署）

1. 改内容文件（`content/` 下）或页面模板（`src/` 下）。**不用动域名配置**（见 5.6）。
2. 本地想先看一眼：`node build.mjs && node dev.mjs`，浏览器开 `http://localhost:4321`。
3. 推上去：
```bash
git add -A
git commit -m "update: 小队介绍补入寒招行程"
git push origin main
```
4. **看到什么算成功**：仓库的 **Actions** 页出现一条 `Deploy to Netlify` 运行，约 1–2 分钟变绿；Netlify 的 **Deploys** 里出现一条新的 **Published**，来源是 API 上传。
5. 线上还是旧内容：Ctrl+F5 / 无痕窗口再确认，仍然不对看第八部分「部署成功但页面是旧的」。

> 注意两件事：① Netlify 侧的「自动构建」是**关掉的**（`stop_builds`），因为那个仓库绑定没拿到 GitHub App 授权、构建会失败；真正的部署者是 GitHub Actions。② Actions 用仓库 Secrets 里的 `NETLIFY_AUTH_TOKEN` 和 `NETLIFY_SITE_ID`，都在 Settings → Secrets and variables → Actions 里。

### 9.2 手动兜底（没网络推 GitHub 时）

1. 改页面文件（例如「小队介绍」补一句寒招行程）。**不用动域名配置**（见 5.6）。
2. 本地构建并自检：
   ```bash
   npm run build
   ```
   然后打开 `dist/index.html`，把每个页面点一遍（这一步能提前发现 4.4 那类路径问题）。
3. 发布，二选一：
   - `NETLIFY_TOKEN=你的token node scripts/netlify-deploy.mjs dadaohuifu`
   - `netlify deploy --prod`
4. **看到什么算成功**：终端给出本次部署地址；Netlify 项目 Deploys 最新一条状态 **Published**，时间是你刚才那次。
5. 打开正式域名看不到新内容时：Ctrl+F5 / 无痕窗口再确认；仍然不对就看第八部分「部署成功但页面是旧的」。

```bash
npm run build
NETLIFY_TOKEN=你的token node scripts/netlify-deploy.mjs dadaohuifu
```

本地构建 + 直接调 API 上传，不经过 GitHub。Token 在 Netlify 的 **User settings → Applications → Personal access tokens** 生成。

回 Netlify 项目 → **Deploys**，会看到一条新部署自己跑；等它变 **Published** 即上线。

### 9.3 发布出问题时：回滚与重试

- **回到上一个正常版本**：Deploys → 点开那个旧部署详情 → **Publish Deploy**。官方说明：这不会触发新构建，而是把这个仍然可用的部署重新发布为线上版本，**瞬间生效**。
- **重跑构建（含清缓存）**：Deploys 里对目标部署选择重试，官方提供「**Retry deploy with cleared cache**」选项——怀疑是缓存里的旧产物时用它。
- 注意：如果站点接了 Git 且开着自动发布，**下一次推送会覆盖你回滚的版本**；真要退回去，同时把代码 `git revert` 掉。

### 9.4 交接与长期维护（小队站特别重要）

- 域名开自动续费，并在日历里记下到期前 2 周的提醒——域名过期被释放是最贵的一类事故。
- 把「Netlify 账号（注册邮箱/登录方式）、站点名 `dadaohuifu`、部署 Token 存放位置、域名、注册商账号」写成一张交接清单，交给下一届负责人。寒招小队每年换届，这一步比技术细节更关键。
- Token 是能改你站点的钥匙：写进交接清单，但**不要贴在公开的群公告或仓库里**。换人时在 User settings → Applications 里吊销旧的、发新的。
- `dist/` 是构建产物，已经被 `.gitignore` 忽略，保持这样就好（仓库里只留页面源码）。
