# 域名与部署指南（Vercel 版）

> 适用对象：「北京科技大学 寒假招生宣传小队」里负责运维的同学（不写代码，也没有网站维护经验）。
> 站点形态：小队的官方小队站，纯静态中文站点，包含「小队介绍」「学生答疑」「资料分享」等页面；无后端、无数据库。当前构建产物是 7 个页面 + 一个 404 页 + `rss.xml` / `sitemap.xml` / `robots.txt`。
> 构建方式：在仓库根目录执行 `npm run build`（内部是 `node build.mjs`），**没有第三方依赖、不需要 `npm install`**，产物目录是 `dist`。
> 托管平台：**Vercel**（Hobby 免费计划足够）。
>
> 阅读方式：第一次配置从「一」按顺序读到「八」；配置好之后日常只看「九」。

## 为什么不用 Cloudflare

原因只有一个，而且是网络层面的：队里那台电脑的出口 IP 被 Cloudflare 拒绝——调用 Cloudflare API 返回错误码 **9109**（位置被拒绝），打开控制台 `dash.cloudflare.com` 直接 403。换成 Vercel 实测 `vercel.com` 与 `api.vercel.com` 全部可达，所以托管平台改用 Vercel。
这不是谁好谁坏的问题：那台机器的网络出口放在 Cloudflare 上就配不完，放在 Vercel 上能配完，如此而已。下文只写 Vercel 的操作。

## 一、选域名：判定清单

一条一条过，全部打勾再买。域名买错要换，等于后面的配置全部重做。

| 判定项 | 怎么判定 | 合格标准 |
| --- | --- | --- |
| 后缀 | 先想清楚要 `.com`、`.cn`、`.net` 还是 `.me` | 小队站首选 `.com`；`.com` 被占了再考虑 `.cn` / `.net` |
| 是否必须 `.com` | 这个网址会不会印在宣传单、贴进答疑群、做成二维码 | 要给同学看、要长期用，优先 `.com` |
| 长度 | 数一数主域名（不含后缀）有几个字符 | 建议 4–15 个字符；整体不超过 25 个字符（二维码更好扫、念出来更短） |
| 易读易念 | 在电话里念一遍，让同学复述一次 | 对方能一次听对，且不会拼错 |
| 拼写歧义 | 有没有连字符 `-`、数字 `0` 与字母 `o`、`1` 与 `l` | 尽量不用连字符和数字；必须用时只用一处 |
| 小队可识别 | 域名里是否含 `ustb` 或小队名拼音 | 一眼能看出是北科大寒招小队 |
| 记忆成本 | 隔一天不看，还能默写出来吗 | 能默写 |
| 价格与续费 | 注册商页面上的「首年价」和「续费价」分别看 | 只看续费价能不能接受；**价格以官网/注册商页面为准** |
| 续费陷阱 | 是否自动续费、是否绑「多年优惠」、转入转出是否有费用 | 打开自动续费防丢域名；不接受必须一次买 5 年才便宜 |
| 商标与校名风险 | 这个词是不是知名品牌；队名缩写会不会被误认为学校官方主站 | 不带他人商标；也别做得像「北科大官网」，避免误导 |

两条只对本站有意义的判断：

- 招生宣传场景下域名常被写进海报和二维码，**短**比「好看」更重要。
- 不要为「看起来专业」选生僻后缀，新手最容易踩的坑是续费价格暴涨。

## 二、在哪买：渠道取舍与注册前准备

### 2.1 四个渠道对比

| 渠道 | 适合谁 | 优点 | 要注意 |
| --- | --- | --- | --- |
| Vercel 内建域名购买（`vercel.com/domains`） | 已经决定用 Vercel、想少一个账号的人 | 和托管平台同一家，买完在 Vercel 面板里就能管 DNS；官方文档说明售价与注册商价格一致；具体可选后缀与是否可买**以页面为准** | 界面全英文；可选后缀比大注册商少；没有中文客服 |
| 阿里云 | 想要中文界面、支付宝付款的人 | 全中文、支付宝/微信付款、客服说中文、`.cn` / `.com` 齐全 | 需要做域名**实名认证**（境内注册商的通行要求，认证通过才算注册成功）；DNS 在阿里云云解析，接 Vercel 时按 5.3 手动加记录 |
| 腾讯云 | 同上，习惯腾讯系产品的人 | 全中文、微信支付、与 DNSPod 打通 | 同样需要实名认证；接 Vercel 的方式同阿里云 |
| Namecheap | 想要英文界面但不想被 Vercel 可选后缀限制的人 | 后缀选择多、whois 隐私免费、常有大额首年优惠 | 促销首年便宜、**续费会明显变贵**；英文界面；国际支付 |

建议（按省事程度排序）：

1. **Vercel 内建购买**：省一个账号，DNS 就在同一个面板，第 5 节的记录表不用去别处抄。
2. **阿里云 / 腾讯云**：全中文、付款方便、有客服；代价是 DNS 记录要手动加三条（A + CNAME，见 5.3）。
3. **Namecheap**：只在你想要的后缀 Vercel 不卖时才选。

注意：域名是**小队共用资产**。用小队公共邮箱（或能长期交接的邮箱）注册，账号密码交给下一届负责人。用个人 QQ 邮箱注册、人毕业了就找不回，是小队站最常见的「死域名」原因。

### 2.2 注册前要准备什么

| 准备项 | 说明 | 大概要多久 |
| --- | --- | --- |
| 一个能长期收信的邮箱 | 注册商与 ICANN 都会发验证信；邮箱没验证，域名可能被挂起（nameserver 被换成停放服务器） | 当场，几分钟 |
| 实名认证材料（境内注册商） | 阿里云 / 腾讯云注册 `.com` `.cn` 等需要提交实名信息并等审核，材料清单**以注册商页面为准** | 通常当天，个别 1–2 个工作日 |
| 支付方式 | Vercel / Namecheap：支持国际支付的卡或对应渠道；阿里云 / 腾讯云：支付宝、微信、银行卡 | 当场 |
| 备选域名 2–3 个 | 第一个被占时不用临时乱选 | — |
| 一个 Vercel 账号 | 用同一个邮箱注册，登录方式选 GitHub 最省事 | 几分钟 |

价格一律不写数字：**以官网为准**。看价格请看「续费价」。

## 三、备案说明：什么时候需要，什么时候不需要

这一节只讲边界，不做法律结论。判断标准一句话：**看网站最终由哪台机器、在哪个地区对外提供服务。**

### 3.1 本项目的现状

小队站托管在 Vercel，内容从 Vercel 的全球节点分发，**不落在任何中国大陆境内的服务器上**。这种情况下通常不需要办理 ICP 备案，域名可以正常解析和访问。

Vercel 官方也明确写过同一件事的边界：托管在中国大陆境内需要 ICP 许可证并遵守当地要求，而 **Vercel 不提供境内托管**。

### 3.2 什么情况会变成「需要备案」

出现下面任一情况，就该把备案当成前置条件，先备案再切流量：

- 把站点搬到**中国大陆境内**的云服务器（ECS / CVM / 轻量应用服务器）。
- 给站点接入**中国大陆境内**的 CDN 加速节点、或境内对象存储的静态托管。
- 用境内的「建站」类产品托管内容。
- 把站点交给**学校网络中心托管到校园网服务器**——同属境内托管，不但要备案，通常还要走学校审批。

原因很直接：备案是**按接入服务商**办理的，境内服务商开通网站服务前会要你提供已备案的域名；境外托管没有这个接入环节。

### 3.3 几个容易混淆的点

- **买域名不等于要备案**：境内注册商要你做的是**实名认证**，那是域名管理要求；备案是网站接入环节的要求。
- **域名注册商在境内、托管在境外**：仍属「境外托管」，通常不需要备案。
- **备案不是一劳永逸**：换接入商、换服务器地域，备案信息要变更。
- **不确定就问**：日后若要用境内服务，直接问云厂商备案控制台/客服或学校网络中心，他们的口径才是最终口径。官方入口：<https://beian.miit.gov.cn/>（打开慢或被拦属常见现象，换网络再试）。

### 3.4 一条实操建议

如果未来有搬到境内（或交给学校托管）的可能，**买域名时就注册在境内注册商并完成实名认证**，日后备案时域名这一环不会卡住。境外注册商的域名，部分省份备案流程更麻烦，**以接入商要求为准**。

### 3.5 如果要在国内访问更快

先说结论：**Vercel 本身不保证中国大陆的可用性与速度**，官方文档的原话是：即使做了这些优化，Vercel 也无法保证在中国大陆的可用性或性能；托管在境外的站点可能遇到延迟、限速或被阻断。所以这一节讲取舍，不承诺结果。

三条路，按「改动量从小到大」排：

| 路线 | 具体做什么 | 要不要备案 | 代价与限制 |
| --- | --- | --- | --- |
| **A. 保持 Vercel 不动** | ①换用自己的域名（不要只发 `*.vercel.app` 网址，官方说自定义域名更不容易被标记或拦截，但没有哪个域名能免疫）②把字体、统计脚本等第三方资源改成站点自带（不要再依赖可能被墙的境外服务） | 不需要 | 改动最小、零成本；但高峰期或特殊时期仍可能慢、甚至打不开，且这不在 Vercel 能控制的范围内 |
| **B. 换成国内对象存储 + CDN** | 把 `dist` 上传到境内对象存储，前面挂境内 CDN，域名解析指过去 | **需要**（境内托管/接入） | 国内访问最快最稳；代价是要备案（域名实名 + 接入商备案，需要时间）、要维护另一套账号，且每次发布要传两处或改脚本 |
| **C. 双托管（Vercel + 境内镜像）** | 同一份 `dist` 同时部署到 Vercel 和境内一个镜像，用不同域名或分流策略对外 | 境内部署的那一份**需要** | 两边都能用、可做对照；代价是两份都要维护、内容要同步，两份都出问题时排查更复杂 |

几点要知道的边界：

- Vercel 官方另有一条路是「在境外换个路由更好的基础设施做静态镜像」——这不需要备案，但要维护两套构建，和小队的人力不匹配，除非以后有人专门管。
- Vercel 官方**不推荐**在部署前面套一层反向代理（这会带来证书、缓存与排查上的额外问题，且官方有专门说明）。想靠「套个代理」解决国内速度，不是一条被推荐的路。
- 三条路不是非此即彼：大多数人先做 A（换域名 + 自托管资源），只有在「答疑群里的同学经常打不开」成为真问题时，才考虑 B 或 C。

## 四、两条部署路径

先说前提：两条路都需要一个 Vercel 账号。**路径 A 和路径 B 可以同时用**（同一个项目既接 Git、也在本地用 CLI 部署都行），这一点和部分平台不同，不必二选一。

### 4.1 路径 A：用 Vercel CLI 部署（改完立刻上传）

前提：电脑上装了 Node.js（本项目构建已经需要它）。

**第一次：登录**

```bash
# 二选一：全局安装后用 vercel 命令
npm i -g vercel
vercel login

# 或者不安装，直接用 npx
npx vercel login
```

`vercel login` 会打开浏览器让你授权，按提示点确认即可。

**第一次部署：在仓库根目录执行**

```bash
cd <你的仓库根目录>
vercel
```

第一次会问你几个问题（项目名、代码目录等），按提示回车即可。官方说明：**新项目的第一次部署本身就是生产部署**，即使不加 `--prod`。

**之后的日常部署（发布到正式域名）**

```bash
vercel --prod
```

**看到什么算成功**：终端打印出一个 Production 的部署地址（形如 `xxx.vercel.app`）；到 Vercel 面板 → 你的项目 → **Deployments**，最新一条状态是 **Ready**，并且被标为 Production。

**不想在这台机器上登录时：用 Token**

1. 打开 <https://vercel.com/account/tokens> 创建一个 Token，复制出来（只显示一次）。
2. 用环境变量或参数都行（官方说明：两者都给时 `--token` 优先；CI 里推荐用环境变量，避免 Token 出现在命令行参数和日志里）：

```bash
# 方式一：环境变量（Windows PowerShell）
$env:VERCEL_TOKEN = "你的Token"
vercel deploy --prod

# 方式二：直接带参数
vercel deploy --prod --token 你的Token
```

注意环境变量名是 **`VERCEL_TOKEN`**（官方文档写法）。写错一个字母就等于没设置，命令会提示未登录。

**在非交互环境（脚本 / 定时任务）里补两个参数可跳过项目绑定提问**：`--project <项目名>`，或设置环境变量 `VERCEL_ORG_ID` 与 `VERCEL_PROJECT_ID`。

> 还有一种 `--prebuilt` 用法（先 `vercel build` 再上传产物）。不要用它：官方文档指出该模式下构建期的系统环境变量会缺失，对本站没有必要。

### 4.2 路径 B：连接 Git 仓库（推送即自动部署）

1. 打开 <https://vercel.com/new>（面板右上角的 **New Project** 按钮也是同一个入口）。
2. 选 **GitHub**（或 GitLab / Bitbucket）授权，在仓库列表里选小队站仓库 → **Import**。
3. 在配置页填这几项：
   - **Project Name**：例如 `ustb-winter-team`。这决定默认网址 `ustb-winter-team.vercel.app`。
   - **Framework Preset**：选 **Other**。官方文档说明：识别不出框架时就会是 Other，并且 **Build Command 的 Override 开关默认打开**，让你手填命令。
   - **Root Directory**：站点代码在仓库根目录就留空；在子目录（例如 `website/`）就填子目录名。
   - **Build Command**：打开 Override，填 `npm run build`。
   - **Output Directory**：打开 Override，填 `dist`。
   - **Install Command**：不用改。Vercel 会自动从 `package.json` 装依赖；本项目没有依赖，这一步会很快结束（看到它跑了也不用管）。
4. 点 **Deploy**。
5. **看到什么算成功**：构建日志跑完，状态变 **Ready**，页面上给出 `*.vercel.app` 预览地址，打开能看到「小队介绍」页。

之后每次把提交推到生产分支（默认 `main`，可在 **Settings → Git** 改），Vercel 会自动构建并发布。

> 两种方式都没有「不可逆」的坑：接 Git 之后仍然可以用 CLI 部署，反之亦然。唯一需要固定下来的是**项目名**（改名会换掉默认域名，自定义域名也要重新绑）。

## 五、绑定自定义域名（含 DNS 记录表）

### 5.1 第一步：把域名加到项目里

1. 打开你的项目 → **Settings** → **Domains**。
2. 点 **Add Existing**（添加一个你已经买好的域名）。
3. 输入根域名 `example.com`。
4. 官方文档说明：如果你添加的是根域名（apex），Vercel 会**提示你把 `www` 前缀也加上**。建议直接接受，两个一起加，后面在 5.4 配跳转。
5. 加完后这个域名会出现在 Domains 列表里，状态可能是 **Valid Configuration**，也可能是 **Invalid Configuration / Pending** 并显示「需要你添加的 DNS 记录」。**下一步就照它显示的值去配。**

### 5.2 关键前提：DNS 记录值必须照面板显示抄

这是整篇文档里最容易出事的一行，先看清楚：

- **A 记录的值不是全站统一的**。Vercel 是**按项目分配 anycast IP** 的，所以不同项目可能不同。官方文档原文：用你项目 **Settings → Domains** 里显示的 A 记录值；**很多项目显示 `76.76.21.21`，较新的项目可能显示 `216.198.79.1` 这样的地址**；抄别的项目或旧教程的 IP，会让域名停在 **DNS Change Recommended / DNS Change Required / Invalid Configuration**。
- **CNAME 的值也是每个项目独有的**。官方文档原文：每个项目有一个唯一的 CNAME 记录，例如 `d1d4fc829fe7bc7c.vercel-dns-017.com`（文档里另一处也以 `cname.vercel-dns-0.com.` 举例）。

所以：**打开 Settings → Domains，把那里显示的「类型 / 名称 / 值」原样抄到你的 DNS 服务商**。下表给的是格式示例，值请替换成你页面上看到的。

### 5.3 做法一（推荐）：DNS 留在原注册商，只加两条记录

| 类型 | 名称（主机记录） | 值 | TTL | 说明 |
| --- | --- | --- | --- | --- |
| `A` | **@**（即根域名 `example.com`） | 项目 **Settings → Domains** 显示的 IPv4，常见为 `76.76.21.21`，较新项目可能是 `216.198.79.1` | 自动 / 600 | 根域名只能用 A 记录接到 Vercel |
| `CNAME` | `www` | 项目 **Settings → Domains** 显示的项目专属目标，形如 `d1d4fc829fe7bc7c.vercel-dns-017.com` | 自动 / 600 | 别写死成别人的值 |

三点提醒：

- 值**不要**带 `https://`，也**不要**带结尾斜杠。
- **不要给同一个主机名同时留 A 和 CNAME**，也不要再加一条指向别处的 AAAA —— 冲突记录会让状态一直是 Invalid Configuration。官方明确说：**Vercel 目前不支持 IPv6**，你不能把 AAAA 指向 Vercel。
- 各家 DNS 的「名称」写法不同：阿里云/腾讯云在主机记录里填 @ 与 www；有的服务商要求填完整 www.example.com。**若你的界面与上文不同，就找含「记录类型 / 主机记录 / 记录值」的入口，按面板提示的名称格式填。**

### 5.4 做法二：把 nameserver 交给 Vercel（Vercel DNS）

适合「这个域名只给小队站用，不打算在别处管 DNS」的情况。

1. 在 **Settings → Domains** 添加域名时选择使用 Vercel 的 nameserver 方式（官方说明：使用通配符域名时会自动启用 Vercel nameserver，并把地址给你复制到注册商）。
2. 到注册商把 nameserver 改成 Vercel 给的两条。文档中出现过的值是 `ns1.vercel-dns.com` 与 `ns2.vercel-dns.com`——**以你面板上显示的为准**。
3. 之后 Records 由 Vercel 管理，证书也能自动续。

代价：**你在原 DNS 上的一切记录都要搬过来**（邮箱验证、其他子域名等）。nameserver 变更的传播最长可达 24–48 小时（官方原文），期间不同地区可能看到不同结果。
好处：不用手抄 A / CNAME 的值，从根上避开 5.2 那个坑。

### 5.5 www 与根域名保持一致

1. 两个都加到 **Settings → Domains**（`example.com` 和 `www.example.com`）。
2. 在 **Settings → Domains** 里，选中你不想要的那个域名 → **Edit** → 用 **Redirect to** 下拉框选另一个。官方原文就是：在项目设置的 Domains 里对要跳转的域名点 Edit，用 Redirect to 下拉选目标。
3. **看到什么算成功**：访问 `https://www.example.com` 会自动跳到 `https://example.com`（或反过来），并且跳转后地址栏是你要的那一个。

### 5.6 怎么确认配置真的生效

终端里（Windows 用 PowerShell 或 CMD 都行）：

```bash
nslookup example.com 1.1.1.1
nslookup www.example.com 1.1.1.1
```

或者用官方 CLI 的检查命令（把 `my-site` 换成你的项目名）：

```bash
vercel domains verify example.com --project my-site
```

**看到什么算成功**：Domains 列表里域名状态是 **Valid Configuration**；`nslookup` 返回的地址与面板显示的一致；`www` 那条的 `Canonical name` 指向项目专属的 CNAME 目标。

### 5.7 日后在同一域名下加页面 / 换内容，会影响域名吗？

**不会。** 域名绑定是**项目级**的，不是页面级的。

- 你绑的是「`example.com` → `ustb-winter-team` 这个项目」，不是某个页面。
- 新增页面、删页面、改「小队介绍」文案、换配色换图片，**都不用重新配域名**。DNS 记录和 Domains 里的那两条保持不动。
- 你只需要**重新构建并部署**（路径 A 跑 `vercel --prod`，路径 B 推代码）。部署变 Ready 后新页面立刻可访问。
- 新页面能不能打开，只取决于产物里有没有对应文件（例如 `dist/qa/index.html`），和域名无关。
- 唯一别动的是：**项目名**、**Domains 里的域名条目**。改页面文件本身完全安全。

一句话记法：**域名绑的是项目，内容改的是文件；改文件不用碰域名。**

## 六、HTTPS / 证书 / 域名跳转

### 6.1 证书是自动的

官方原文：**DNS 验证通过后，Vercel 会自动签发 SSL 证书**，通常在几分钟内完成。你不需要上传任何证书文件。

判断方法：

- 浏览器打开 `https://example.com`，地址栏有小锁。
- 或在终端跑 `vercel certs list`，输出里有你的域名。

### 6.2 证书签不出来，最常见的两个原因

1. **CAA 记录挡了签发**。如果你给域名加过 CAA 记录，需要允许 Let's Encrypt，官方给的值是：
   ```text
   0 issue "letsencrypt.org"
   ```
   （如果你从来没加过 CAA 记录，这条不用管。）
2. **误加了 AAAA 记录**。Vercel 目前不支持 IPv6，把 AAAA 指向 Vercel 会导致配置无效。

### 6.3 关于 http → https

Vercel 给自己的部署以 HTTPS 提供服务，证书是自动的。**至于 `http://` 打开时会不会自动跳转到 `https://`，请你自己用浏览器实测一次**：在地址栏输入 `http://example.com` 回车，看地址栏是否变成 `https://`。
（这一条属于平台行为细节，本文没有在官方文档里找到一句可直接引用的说明，所以不做承诺；若你的站点停在 http 不跳转，记录现象后去 Vercel 社区/支持确认，不要凭猜测改 DNS。）

> 顺带一句：HSTS 这类「浏览器强制只用 https」的设置不需要开，配错很难回退，小队站用不到。

## 八、常见故障排查表

| 现象 | 最可能的原因 | 怎么确认 | 怎么修 |
| --- | --- | --- | --- |
| 域名一直是 **Pending** 或 **Invalid Configuration** | A 记录用了别处的 IP（最常见）；缺 `www` 那条 CNAME；同一主机名上还有冲突的 A / AAAA / CNAME；或 DNS 还没传播 | 打开 **Settings → Domains** 看它要求的记录，与你 DNS 里的逐项对照；`nslookup example.com 1.1.1.1` 看返回是否与面板一致 | 照面板显示的值改（A 用项目专属 IP、CNAME 用项目专属目标）；删掉冲突记录；等传播（普通记录较快，改 NS 最长 24–48 小时） |
| 域名状态里写着 **DNS Change Recommended / DNS Change Required** | 还在用旧地址（例如把旧教程的 IP 抄了过来） | Domains 页面会直接指出建议值 | 改成页面显示的值，再等几分钟刷新 |
| **Deployment 构建失败**（状态 Error） | Build Command 没设成 `npm run build`；Output Directory 没设成 `dist`；仓库里缺 `package.json`；构建脚本自己报错 | 打开那条部署看 **Logs**，看是「找不到命令」还是脚本报错 | Settings → Build & Development Settings 里把 Build Command / Output Directory 的 Override 补上；本地先跑一次 `npm run build` 确认脚本本身没问题 |
| 部署成功了，但打开域名是 404 | Output Directory 填错（例如填了 `public` 或留空）；或产物里 `index.html` 不在根 | Deployments → 打开部署 → 看输出文件列表里有没有 `index.html` | 把 Output Directory 改成 `dist` 后重新部署 |
| 只有某个页面 404 | 产物里没有那个文件（页面文件位置/命名不对，或 `build.mjs` 没输出它） | 本地 `npm run build` 后看 `dist/` 里有没有对应 `index.html` | 修页面文件后重新构建部署 |
| 证书签不出来 / 一直没小锁 | 有 CAA 记录不允许 Let's Encrypt；或误加了指向 Vercel 的 AAAA | `vercel certs list` 看有没有你的域名；查 DNS 里有没有 CAA / AAAA | 加 `0 issue "letsencrypt.org"`；删掉 AAAA；等几分钟重试 |
| 改了页面内容，线上还是旧版 | ① 部署根本没触发（推到了别的分支 / 自动部署被关）② 浏览器缓存 ③ 构建缓存里是旧产物 | Deployments 里最新一条的时间戳是不是你刚才那次 | 确认提交推到了生产分支；Ctrl+F5 或无痕窗口；必要时在 Deployments 里对该部署点三个点 → **Redeploy**，在 **Redeploy to Production** 窗口里决定是否复用 **Build Cache**（怀疑缓存问题就取消勾选） |
| 中国大陆访问慢，或 `*.vercel.app` 打不开 | 境外托管到中国大陆的网络现实；`vercel.app` 域名被干扰的概率高于自有域名 | 换手机流量/换网络对比；只发 `vercel.app` 网址时问题更明显 | 先做 3.5 的路线 A（换自定义域名 + 自托管第三方资源）；仍是硬需求再考虑路线 B / C（B 需要备案） |
| `www` 与裸域内容不一致 / 一个打不开 | 只加了一个域名；或另一个还是旧的 A 记录 | Settings → Domains 里是否两条都在 | 两个都加，再用 **Edit → Redirect to** 把其中一个跳到另一个 |
| 部署成功但样式全丢 | 资源用了站点根绝对路径，但站点被部署在子路径；或 `public/` 里的静态资源没进产物 | F12 看 Console / Network 里 404 的资源 | 修正产物路径后重新部署 |

## 九、日常发布流程

### 9.1 走路径 B（Git 自动部署）时

1. 改页面文件（例如「小队介绍」补一句寒招行程）。**不用动域名配置**（见 5.7）。
2. 本地先看一眼（推荐）：
   ```bash
   npm run build
   ```
   然后直接打开 `dist/index.html` 逐个页面点一遍。
3. 提交并推送：
   ```bash
   git add .
   git commit -m "update: 小队介绍补入寒招行程"
   git push
   ```
4. 回 Vercel → 项目 → **Deployments**，会看到一条新部署自己开始跑。
5. **看到什么算成功**：状态变 **Ready**，预览地址能看到新内容；域名打开就是最新的。

### 9.2 走路径 A（CLI）时

```bash
cd <你的仓库根目录>
npm run build        # 先本地确认产物没问题
vercel --prod        # 发布到正式域名
```

确认 Deployments 最新一条是你刚才那次、状态 Ready。

### 9.3 发布出问题时：重新部署与回到旧版

- **重新部署同一次提交**：Deployments → 找到那条部署 → 右侧三个点 → **Redeploy** → 在 **Redeploy to Production** 窗口决定是否用 **Build Cache** → **Redeploy**。官方说明：怀疑是缓存里的脏数据时，就用它手动重跑。
- **回到上一个正常版本**：Deployments → 找到那个旧部署 → 三个点 → 选 **Promote to Production**（把旧部署提升为生产）。若你的界面里没有这一项，就用它的 Redeploy 重新发布一次。**注意**：Promote 之后，下一次推代码仍会覆盖它——所以真出问题时，最好同时把代码回退（`git revert`）。

### 9.4 交接与长期维护（小队站特别重要）

- 域名开自动续费，并在日历里记下到期前 2 周的提醒——域名过期被释放是最贵的一类事故。
- 把「Vercel 账号（登录方式）、注册商账号、域名、项目名、仓库地址」写成一张交接清单，交给下一届负责人。寒招小队每年换届，这一步比技术细节更关键。
- `dist/` 是构建产物，建议不要提交进 Git 仓库（用 `.gitignore` 忽略它），仓库里只留页面源码。**这条涉及改 `.gitignore`，本指南不替你改，你确认后自行决定。**
